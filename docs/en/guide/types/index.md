# Type Declarations

This page lists all built-in type declarations in GraphVis. For ease of reference, the types are organized in the order of "foundation → composition → application":

1. **Graph and Data**: `GraphologyType`, `GraphAttributes`, `NodeAttributes`, `EdgeAttributes`
2. **Geometry Foundation**: `Point`
3. **General Utilities**: `AttrType`, `DataDriven`, `GFillStyle`, `GStrokeStyle`
4. **Rendering and Nodes**: `NodeType`, `DrawBy`, `TextType`
5. **Label Related**: `LabelType`, `Placement`, `EdgeLabelPositionMode`
6. **Animation**: `EasingType`

## Graph and Data

### GraphologyType

```ts
type GraphologyType = "mixed" | "undirected" | "directed";
```

The graph type, used to indicate whether the current graph is directed, undirected, or mixed. The meaning of each value is as follows:

| Value          | Meaning                                                                                                     |
| :------------- | :---------------------------------------------------------------------------------------------------------- |
| `'directed'`   | Directed graph. Edges in the graph have a direction, pointing from the source node to the target node.      |
| `'undirected'` | Undirected graph. Edges in the graph have no direction; the two connected nodes are in a peer relationship. |
| `'mixed'`      | Mixed graph. The graph contains both directed and undirected edges.                                         |

### GraphAttributes

```ts
type GraphAttributes = {
  nodes: NodeAttributes[];
  edges: EdgeAttributes[];
};
```

`GraphAttributes` represents the raw data of the graph, containing an array of node data and an array of edge data.

| Property | Type                                  | Description         |
| :------- | :------------------------------------ | :------------------ |
| `nodes`  | [`NodeAttributes[]`](#nodeattributes) | Array of node data. |
| `edges`  | [`EdgeAttributes[]`](#edgeattributes) | Array of edge data. |

### NodeAttributes

```ts
type NodeAttributes = { [key: string]: any };
```

`NodeAttributes` represents the raw data of a node, storing arbitrary properties as key-value pairs. The key is the property name and the value can be of any type.

### EdgeAttributes

```ts
type EdgeAttributes = { [key: string]: any };
```

`EdgeAttributes` represents the raw data of an edge, storing arbitrary properties as key-value pairs. The key is the property name and the value can be of any type.

## Geometry Foundation

### Point

```ts
type Point = { x: number; y: number };
```

`Point` represents a point in a two-dimensional coordinate system, containing two numeric coordinates, `x` and `y`.

| Property | Type     | Description       |
| :------- | :------- | :---------------- |
| `x`      | `number` | The x-coordinate. |
| `y`      | `number` | The y-coordinate. |

> This type is an object literal type. When using it, you need to pass an object that contains both `x` and `y`.

## General Utilities

### AttrType

```ts
type AttrFunc<T = any, D = any> = (d?: D) => T;
type AttrType<T = any, D = any> = T | AttrFunc<T, D>;
```

`AttrType` indicates that a property can be either a static value of type `T` or a function. The function receives data `D` and returns a value of type `T`. The function parameter `d` is usually the raw data of a node or edge, and you can compute the property value dynamically based on the data.

#### Generic Parameters

| Parameter | Default | Description                                                                        |
| :-------- | :------ | :--------------------------------------------------------------------------------- |
| `T`       | `any`   | The target type of the property.                                                   |
| `D`       | `any`   | The type of data received by the function, usually the raw data of a node or edge. |

#### Example

**Static value:**

```js
new GraphVis({
  node: {
    style: {
      fill: "red",
    },
  },
});
```

**Dynamically generated by a function:**

```js
new GraphVis({
  node: {
    style: {
      fill: (d) => (d.category === "important" ? "#ff4d4f" : "#409eff"),
    },
  },
});
```

> `d` is the raw node data. `d.category` is not a built-in node property; you can only use it this way if the `category` field actually exists in your data.

### DataDriven

```ts
import { FillGradient, FillPattern, Matrix } from "pixi.js";

type NonRecursiveTypes = FillGradient | FillPattern | Matrix;

type DataDriven<T, D = any> = T extends undefined
  ? undefined
  : T extends (...args: any[]) => any
    ? AttrType<T, D>
    : T extends any[]
      ? AttrType<T, D>
      : T extends NonRecursiveTypes
        ? AttrType<T, D>
        : T extends object
          ? { [K in keyof T]: DataDriven<T[K], D> }
          : AttrType<T, D>;
```

`DataDriven` is a recursive utility type used to convert every property in an object into [`AttrType`](#attrtype). It allows properties at any level of a configuration object to be provided either as static values or as dynamically generated functions.

#### Generic Parameters

| Parameter | Default | Description                                                                        |
| :-------- | :------ | :--------------------------------------------------------------------------------- |
| `T`       | -       | The target type to be converted.                                                   |
| `D`       | `any`   | The type of data received by the function, usually the raw data of a node or edge. |

#### Non-Recursive Types

`NonRecursiveTypes` is an internally defined set of non-recursive types, consisting of the following types from PixiJS:

| Type           | Source    | Description                   |
| :------------- | :-------- | :---------------------------- |
| `FillGradient` | `pixi.js` | Fill gradient object.         |
| `FillPattern`  | `pixi.js` | Fill pattern object.          |
| `Matrix`       | `pixi.js` | Transformation matrix object. |

These types are themselves objects, but their internal properties do not need to be recursively converted to `AttrType`. Instead, they are treated as a whole as `AttrType`, meaning they can be passed in statically or returned by a function.

#### Conversion Rules

`DataDriven` processes `T` differently depending on its type:

| Condition                           | Conversion Result                         | Description                                                                                                                                  |
| :---------------------------------- | :---------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------- |
| `T extends undefined`               | `undefined`                               | If the property type is `undefined`, it remains `undefined`.                                                                                 |
| `T extends (...args: any[]) => any` | [`AttrType<T, D>`](#attrtype)             | If the property is itself a function, it is treated as the function form of `AttrType`.                                                      |
| `T extends any[]`                   | [`AttrType<T, D>`](#attrtype)             | If the property is an array, the entire array can be provided statically or returned by a function.                                          |
| `T extends NonRecursiveTypes`       | [`AttrType<T, D>`](#attrtype)             | If the property is `FillGradient`, `FillPattern`, or `Matrix`, it is treated as a non-recursive type and converted as a whole to `AttrType`. |
| `T extends object`                  | `{ [K in keyof T]: DataDriven<T[K], D> }` | If the property is a plain object, `DataDriven` is recursively applied to each property.                                                     |
| Other cases                         | [`AttrType<T, D>`](#attrtype)             | Fallback handling, converted to `AttrType`.                                                                                                  |

#### Purpose and Example

The main purpose of `DataDriven` is to simplify configuration so that developers can obtain full dynamic generation capability without manually writing `AttrType` for every property.

Suppose there is the following style type:

```ts
type A = {
  color: string;
  background: string;
  stroke: {
    width: number;
  };
};
```

After conversion by `DataDriven<A>`, the type becomes:

```ts
type A = {
  color: AttrType<string>;
  background: AttrType<string>;
  stroke: {
    width: AttrType<number>;
  };
};
```

This means that `color`, `background`, and `stroke.width` can all be either static values or functions. For example:

```js
new GraphVis({
  node: {
    style: {
      color: (d) => (d.category === "important" ? "#ff4d4f" : "#409eff"),
      background: "#ffffff",
      stroke: {
        width: (d) => (d.weight > 5 ? 3 : 1),
      },
    },
  },
});
```

### GFillStyle

```ts
type GFillStyle<D = any> = DataDriven<FillStyle, D> | AttrType<FillInput, D>;
```

`GFillStyle` represents the fill style of a node or edge. It can be a `FillStyle` object (whose internal properties support dynamic generation), or a static value or function of `FillInput`.

#### Generic Parameters

| Parameter | Default | Description                                                                        |
| :-------- | :------ | :--------------------------------------------------------------------------------- |
| `D`       | `any`   | The type of data received by the function, usually the raw data of a node or edge. |

#### Description

- `FillStyle`: PixiJS's fill style object, containing properties such as `color` and `alpha`. For more details, see [PixiJS FillStyle](https://pixijs.download/release/docs/scene.FillStyle.html).
- `FillInput`: PixiJS's fill input type, which can be a color value, texture, etc. For more details, see [PixiJS FillInput](https://pixijs.download/release/docs/scene.FillInput.html).
- `DataDriven`: Recursively converts object properties to `AttrType`, allowing every property inside the object to be either a static value or a function. For more details, see [`DataDriven`](#datadriven).

#### Example

**Static object:**

```js
new GraphVis({
  node: {
    style: {
      fill: {
        color: "#ff4d4f",
        alpha: 0.8,
      },
    },
  },
});
```

**Dynamic object:**

```js
new GraphVis({
  node: {
    style: {
      fill: {
        color: (d) => (d.category === "important" ? "#ff4d4f" : "#409eff"),
        alpha: (d) => (d.weight > 5 ? 1 : 0.6),
      },
    },
  },
});
```

**Using a color value directly:**

```js
new GraphVis({
  node: {
    style: {
      fill: "#ff4d4f",
    },
  },
});
```

type GStrokeStyle<D = any> = DataDriven<StrokeStyle, D> | AttrType<StrokeInput, D>;

- `DataDriven`: Recursively converts object properties to `AttrType`, allowing every property inside the object to be either a static value or a function. For more details, see [`DataDriven`](#datadriven).

new GraphVis({

## Rendering and Nodes

### NodeType

```ts
type NodeType =
  | "circle"
  | "ellipse"
  | "image"
  | "polygon"
  | "rect"
  | "text"
  | "bitmap-text"
  | "star"
  | (string & {});
```

`NodeType` represents the node type. It is one of the following built-in shape names, while also allowing any custom string to be passed in.

| Value           | Meaning      |
| :-------------- | :----------- |
| `'circle'`      | Circle.      |
| `'ellipse'`     | Ellipse.     |
| `'image'`       | Image.       |
| `'polygon'`     | Polygon.     |
| `'rect'`        | Rectangle.   |
| `'text'`        | Text.        |
| `'bitmap-text'` | Bitmap text. |
| `'star'`        | Star.        |

> The trailing `(string & {})` in the type preserves literal autocompletion while allowing any custom string to be passed in, so the actual values are not limited to the table above.

### DrawBy

```ts
type DrawBy = "sprite" | "graphics";
```

`DrawBy` represents the drawing method, used to specify whether a node or edge is drawn using PixiJS's `Sprite` or `Graphics`.

| Value        | Meaning                                                                                                                       |
| :----------- | :---------------------------------------------------------------------------------------------------------------------------- |
| `'graphics'` | Drawn using PixiJS's `Graphics` object. Suitable for most vector graphics such as circles, rectangles, polygons, etc.         |
| `'sprite'`   | Drawn using PixiJS's `Sprite` object. Suitable for scenarios requiring textures, images, or high-performance batch rendering. |

> In node and edge configurations, the `drawBy` property has the type [`AttrType`](#attrtype)&lt;`DrawBy`&gt;, so it can be specified directly or returned dynamically by a function.

#### Example

```js
new GraphVis({
  node: {
    drawBy: "sprite", // Draw nodes using Sprite
  },
  edge: {
    drawBy: (d) => (d.weight > 5 ? "graphics" : "sprite"), // Dynamically choose based on weight
  },
});
```

### TextType

```ts
type TextType = string | number | { toString: () => string };
```

`TextType` represents the content types that can be used for text rendering. It can be a string, a number, or any object that implements a `toString` method.

| Type                         | Description                                                                                      |
| :--------------------------- | :----------------------------------------------------------------------------------------------- |
| `string`                     | Used directly as text content.                                                                   |
| `number`                     | The number is converted to a string and used as text content.                                    |
| `{ toString: () => string }` | Any object with a `toString` method. The method is called during rendering to obtain the string. |

> In node or edge label configurations, properties such as `labelText` have the type [`AttrType`](#attrtype)&lt;`TextType`&gt;, so you can pass in values of the above types directly or return them dynamically via a function.

#### Example

```js
new GraphVis({
  node: {
    labelConfig: {
      labelText: "Node A", // string
    },
  },
});

new GraphVis({
  node: {
    labelConfig: {
      labelText: (d) => d.weight, // number
    },
  },
});

new GraphVis({
  node: {
    labelConfig: {
      labelText: (d) => ({ toString: () => `Node ${d.id}` }), // custom object
    },
  },
});
```

## Label Related

### LabelType

```ts
type LabelType = "text" | "bitmap-text";
```

`LabelType` represents the rendering type of a label, used to specify whether a node or edge label is rendered using regular text or bitmap text.

| Value           | Meaning                                                                                                                   |
| :-------------- | :------------------------------------------------------------------------------------------------------------------------ |
| `'text'`        | Renders the label using PixiJS's `Text` object, supporting rich text styles.                                              |
| `'bitmap-text'` | Renders the label using PixiJS's `BitmapText` object, offering better performance and suitable for large amounts of text. |

#### Example

```js
new GraphVis({
  node: {
    labelConfig: {
      type: "bitmap-text", // Render node labels using bitmap text
    },
  },
});
```

You can also set it dynamically using a function:

```js
new GraphVis({
  node: {
    labelConfig: {
      type: (d) => (d.weight > 5 ? "bitmap-text" : "text"),
    },
  },
});
```

### Placement

```ts
type Placement = "center" | "left" | "right" | "top" | "bottom";
```

`Placement` represents the position of a label relative to a node or edge. It is usually used for the `placement` property of node labels.

| Value      | Meaning                                                              |
| :--------- | :------------------------------------------------------------------- |
| `'center'` | Centered; the label is positioned at the center of the node or edge. |
| `'left'`   | Left; the label is positioned to the left of the node or edge.       |
| `'right'`  | Right; the label is positioned to the right of the node or edge.     |
| `'top'`    | Top; the label is positioned above the node or edge.                 |
| `'bottom'` | Bottom; the label is positioned below the node or edge.              |

#### Example

```js
new GraphVis({
  node: {
    labelConfig: {
      style: {
        placement: "right", // Label is displayed to the right of the node
      },
    },
  },
});
```

You can also set it dynamically using a function:

```js
new GraphVis({
  node: {
    labelConfig: {
      style: {
        placement: (d) => (d.id % 2 === 0 ? "right" : "left"),
      },
    },
  },
});
```

### EdgeLabelPositionMode

```ts
type EdgeLabelPositionMode = "local" | "global";
```

`EdgeLabelPositionMode` represents the calculation mode for edge label positions. It determines the coordinate system corresponding to edge label properties such as `alongT`, `offsetX`, and `offsetY`.

| Value      | Meaning                                                                                                                                                                                                                                           |
| :--------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `'local'`  | Local coordinate system, relative to the coordinate system of the current edge. For example, `alongT` represents the relative position along the edge, and `offsetX`/`offsetY` represent offsets along the edge direction or perpendicular to it. |
| `'global'` | Global coordinate system, relative to the coordinate system of the entire graph. For example, the point corresponding to `alongT` uses global coordinates directly, and `offsetX`/`offsetY` represent offsets in the global X/Y directions.       |

#### Example

```js
new GraphVis({
  edge: {
    labelConfig: {
      style: {
        alongT: 0.5,
        alongTPositionMode: "local", // alongT uses the local coordinate system
        offsetX: 10,
        offsetY: 10,
        offsetPositionMode: "global", // offsetX/offsetY use the global coordinate system
      },
    },
  },
});
```

## Animation

### EasingType

```ts
type EasingType =
  | "linear"
  | "back-in"
  | "back-out"
  | "back-in-out"
  | "bounce-in"
  | "bounce-out"
  | "bounce-in-out"
  | "circular-in"
  | "circular-out"
  | "circular-in-out"
  | "cubic-in"
  | "cubic-out"
  | "cubic-in-out"
  | "elastic-in"
  | "elastic-out"
  | "elastic-in-out"
  | "exponential-in"
  | "exponential-out"
  | "exponential-in-out"
  | "linear-in"
  | "linear-out"
  | "linear-in-out"
  | "quadratic-in"
  | "quadratic-out"
  | "quadratic-in-out"
  | "quartic-in"
  | "quartic-out"
  | "quartic-in-out"
  | "quintic-in"
  | "quintic-out"
  | "quintic-in-out"
  | "sinusoidal-in"
  | "sinusoidal-out"
  | "sinusoidal-in-out";
```

`EasingType` represents the easing type of an animation and is one of the following string literals. The naming convention is `{curve}[-{direction}]`: without a direction suffix, it denotes symmetric easing; with `-in`, `-out`, or `-in-out`, it denotes acceleration, deceleration, or acceleration followed by deceleration, respectively.

| Value                  | Meaning                                                                                     |
| :--------------------- | :------------------------------------------------------------------------------------------ |
| `'linear'`             | Uniform animation with no easing effect.                                                    |
| `'back-in'`            | Pulls back at the start before accelerating into the motion.                                |
| `'back-out'`           | Overshoots the target near the end before settling back.                                    |
| `'back-in-out'`        | Pulls back at the start and overshoots at the end, with rebound at both ends.               |
| `'bounce-in'`          | Enters with a bouncing effect at the start.                                                 |
| `'bounce-out'`         | Stops with a bouncing effect at the end.                                                    |
| `'bounce-in-out'`      | Has a bouncing effect at both the start and the end.                                        |
| `'circular-in'`        | Accelerates into the motion using a circular curve.                                         |
| `'circular-out'`       | Decelerates to a stop using a circular curve.                                               |
| `'circular-in-out'`    | Accelerates and then decelerates using a circular curve.                                    |
| `'cubic-in'`           | Accelerates into the motion using a cubic curve.                                            |
| `'cubic-out'`          | Decelerates to a stop using a cubic curve.                                                  |
| `'cubic-in-out'`       | Accelerates and then decelerates using a cubic curve.                                       |
| `'elastic-in'`         | Accelerates into the motion using an elastic curve, with a noticeable rebound at the start. |
| `'elastic-out'`        | Decelerates to a stop using an elastic curve, with a noticeable rebound at the end.         |
| `'elastic-in-out'`     | Uses an elastic curve with rebound at both ends.                                            |
| `'exponential-in'`     | Accelerates into the motion using an exponential curve.                                     |
| `'exponential-out'`    | Decelerates to a stop using an exponential curve.                                           |
| `'exponential-in-out'` | Accelerates and then decelerates using an exponential curve.                                |
| `'linear-in'`          | Accelerates into the motion linearly.                                                       |
| `'linear-out'`         | Decelerates to a stop linearly.                                                             |
| `'linear-in-out'`      | Accelerates and then decelerates linearly.                                                  |
| `'quadratic-in'`       | Accelerates into the motion using a quadratic curve.                                        |
| `'quadratic-out'`      | Decelerates to a stop using a quadratic curve.                                              |
| `'quadratic-in-out'`   | Accelerates and then decelerates using a quadratic curve.                                   |
| `'quartic-in'`         | Accelerates into the motion using a quartic curve.                                          |
| `'quartic-out'`        | Decelerates to a stop using a quartic curve.                                                |
| `'quartic-in-out'`     | Accelerates and then decelerates using a quartic curve.                                     |
| `'quintic-in'`         | Accelerates into the motion using a quintic curve.                                          |
| `'quintic-out'`        | Decelerates to a stop using a quintic curve.                                                |
| `'quintic-in-out'`     | Accelerates and then decelerates using a quintic curve.                                     |
| `'sinusoidal-in'`      | Accelerates into the motion using a sinusoidal curve.                                       |
| `'sinusoidal-out'`     | Decelerates to a stop using a sinusoidal curve.                                             |
| `'sinusoidal-in-out'`  | Accelerates and then decelerates using a sinusoidal curve.                                  |
